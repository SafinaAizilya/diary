## 3. Реализованный функционал

В ходе работы реализованы все 8 обязательных технических требований.

### 3.1. Динамический поиск

Текстовое поле `<input type="text" id="searchInput">`.
Поиск срабатывает в реальном времени по событию `input`. Регистр не имеет значения благодаря `toLowerCase()`.

### 3.2. Фильтрация

Выпадающий список `<select id="moodFilter">` для фильтрации по настроению.
Присутствует пункт «Все настроения» (`value="all"`) для сброса фильтра.

### 3.3. Сортировка

Выпадающий список `<select id="sortSelect">` с четырьмя вариантами:

- Сначала новые (по дате)
- Сначала старые (по дате)
- По алфавиту (А–Я)
- По алфавиту (Я–А)

Используется иммутабельная сортировка через `state.items.slice()` — исходный массив в `state` не мутируется.

### 3.4. Модальное окно добавления

Модальное окно `#modal` открывается по кнопке «Добавить запись».
Закрывается по:

- кнопке-крестику (×),
- кнопке «Отмена»,
- нажатию клавиши Escape,
- клику по подложке (backdrop).

### 3.5. Форма и клиентская валидация

Форма `#addForm` с HTML5-атрибутами (`required`, `minlength`, `maxlength`).
Отправка перехватывается через `event.preventDefault()`.
Проверка валидности выполняется через `form.checkValidity()` и `input.validity` (Constraint Validation API).
Сообщения об ошибках выводятся под каждым полем.

### 3.6. Удаление с делегированием событий

Кнопка «×» на каждой карточке.
Обработка через **делегирование**: один слушатель на контейнере `#cardsContainer`, поиск цели через `event.target.closest('[data-action="delete"]')`.
Перед удалением открывается модальное окно подтверждения `#confirmModal`.

### 3.7. Сохранение в localStorage

При любом изменении (добавление, удаление) массив `state.items` сериализуется через `JSON.stringify()` и сохраняется в `localStorage` по ключу `diary-items-v1`.
При загрузке страницы данные читаются через `JSON.parse()`. Если хранилище пустое — загружаются демонстрационные записи (`DEFAULT_ITEMS`).

### 3.8. State-Driven UI

Всё состояние приложения хранится в едином объекте `state`:

```javascript
const state = {
  items: [],
  searchQuery: "",
  selectedMood: "all",
  sortBy: "date-desc",
};
```

Любое действие вызывает `updateState()`, который меняет `state` и вызывает `render()`.
`render()` читает `state` и полностью перерисовывает список карточек.

**Формула:** `UI = render(state)`.

### Дополнительно: просмотр записи

Реализовано модальное окно `#viewModal` для просмотра полной записи. Открывается по клику на карточку. Содержит полный текст, дату, настроение и теги. Оформлено в виде страницы дневника.

## 6. Обработка событий и делегирование

Делегирование реализовано для кликов по карточкам:

```javascript
cardsContainer.addEventListener("click", (event) => {
  const deleteBtn = event.target.closest('[data-action="delete"]');
  if (deleteBtn) {
    const card = deleteBtn.closest(".card");
    if (card) handleDelete(card.dataset.id);
    return;
  }

  const card = event.target.closest(".card");
  if (card) openView(card.dataset.id);
});
```

- Один слушатель на контейнер.
- Работает для динамически созданных карточек.
- Благодаря event bubbling клики по дочерним элементам (картинка, заголовок) тоже ловятся.

## 9. Ответы на вопросы для защиты

### 1. Разница между `let`, `const` и `var`. Что такое TDZ?

`var` — устаревший, функциональная область видимости, всплывает. `let` — блочная, значение можно менять. `const` — блочная, переприсвоить нельзя.
TDZ (Temporal Dead Zone) — промежуток между началом блока и объявлением `let`/`const`, в котором к переменной нельзя обратиться — будет ошибка.

### 2. Почему `textContent`, а не `innerHTML`?

`innerHTML` вставляет текст как HTML — можно случайно выполнить скрипт (XSS-уязвимость). `textContent` вставляет как обычный текст, теги не выполняются. Для пользовательских данных — только `textContent`.

### 3. Что такое Event Bubbling и Event Delegation?

Bubbling — событие всплывает от целевого элемента к родителям до `document`.
Delegation — вешаем один слушатель на родителя, а через `event.target.closest()` определяем, куда кликнули.
Плюсы: работает для новых элементов и экономит память.

### 4. Чем `preventDefault()` отличается от `stopPropagation()`?

`preventDefault()` отменяет действие по умолчанию (перезагрузка формы, переход по ссылке). `stopPropagation()` останавливает всплытие события на родителей. Это разные вещи.

### 5. Как устроен JSON и почему данные в localStorage нужно передавать через `JSON.stringify()`?

JSON — текстовый формат данных. localStorage хранит только строки. Массив записей превращаем в строку через `JSON.stringify()`, при чтении — обратно в массив через `JSON.parse()`.

### 6. Что такое паттерн State-Driven UI и как функция `render()` связывает состояние с DOM?

Всё состояние — в одном объекте `state`. При любом действии вызываем `updateState()`, который меняет `state` и вызывает `render()`. `render()` читает `state` и перерисовывает DOM.
Формула: `UI = render(state)`.
